# Knowledge-Engineering documentation hub

This directory holds the repository-level guides for the archive. Start with
[index.md](index.md), then follow the area READMEs linked there.
[documentation-index.md](documentation-index.md) lists every long-lived page in
one flat index.

- [index.md](index.md) — hub and reference map.
- [RUN_GUIDE.md](RUN_GUIDE.md) — the gate entry point, its arms, the CI jobs, and
  the GNN pin.
- [gate-timings.md](gate-timings.md) — per-arm wall times, generated by the gate.
- [quickstart.md](quickstart.md) — browse the archive, run the PubMed notebook,
  and run PDF keyword extraction.
- [provenance.md](provenance.md) — per-dataset inventory: formats, dates, sizes,
  and caveats.
- [architecture.md](architecture.md) — how the literature-analysis components
  fit together and cross-reference each other.
- [documentation-index.md](documentation-index.md) — flat index of long-lived
  documentation.

This is a documentation hub over a research-data archive: there is no build step
or package to install. The canonical per-area documentation remains the README
in each area directory under `Literature_Analysis/` and `Ontology_Snapshot/`.

See the repository [README](../README.md) for the contents table, citation, and
license, and [AGENTS.md](../AGENTS.md) for contribution and preservation rules.

## Gate failure mode

[`.github/workflows/ci.yml`](../.github/workflows/ci.yml) runs
[`.github/scripts/gate.py`](../.github/scripts/gate.py) on every pull request and
on pushes to `main`. Job `docs and scripts` runs the fast arm,
`python .github/scripts/gate.py fast`, which checks that relative Markdown links
resolve, tracked Python compiles, notebooks are output-free JSON, no
`.ipynb_checkpoints` directory is tracked, and the gate's own tests pass. It
exits 1 and lists every failure when any of those break.

The proof is run 41719405985, job `docs and scripts`: the log line
`- docs/README.md: missing link target: does-not-exist.md` is followed by
`##[error]Process completed with exit code 1.`. Reproduce it locally with
`python .github/scripts/gate.py links`.

The workflow also runs the pinned GNN conformance baseline, job
`gnn conformance (pinned)`, as
`python .github/scripts/gate.py gnn --install`; it verifies the parser pin and,
as this archive carries no `.gnn.md` model file, validates the pinned upstream
exemplar. [RUN_GUIDE.md](RUN_GUIDE.md) lists every arm, and `.github/GNN.md`
records what the conformance arm parses. Wall times for each arm are in the
generated [gate-timings.md](gate-timings.md).
